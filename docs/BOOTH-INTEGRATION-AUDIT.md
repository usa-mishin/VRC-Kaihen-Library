# BOOTH Library Manager 連携監査

最終確認日: 2026-08-29

## 結論

本アプリは、ユーザー本人のPCにある BOOTH Library Manager（BLM）のデータを、本人の明示同意後にローカルで読み取り専用参照する。BLM DBへの書き込み、資格情報の取得、独自サーバーへの送信は行わない。技術面と表示面の対策は本書の項目を満たす。

BOOTHまたはBLMが第三者アプリ向けにDBスキーマや連携APIを公式提供していることは確認できていない。したがって、互換性の保証と運営元の個別許諾は別問題として残る。公開前に、末尾の文面でBOOTHサポートへ確認し、回答を本書へ追記することを推奨する。

BOOTH公式ガイドライン（2026年7月8日改定）は、ユーザーの利便性向上や創作活動の健全な発展を目的とする情報解析のためのスクレイピングを認めつつ、過度な負荷、権利侵害、損害のおそれがある場合は制限するとしている。本アプリは公開ページを巡回収集せず、ユーザー本人のローカルDBを参照し、サーバー通信は表示対象の公式サムネイル画像に限定する。ただし、このガイドラインはBLMのローカルDB連携を明示的に許諾する文書ではない。

- BOOTHガイドライン: https://booth.pm/guidelines
- BOOTH Library Manager アーリーアクセス案内: https://booth.pm/announcements/893

## 完了した監査項目

- [x] BLM DBは `SqliteOpenMode.ReadOnly`、Private cache、pooling無効で開く。
- [x] DBへ書き込み、置換、削除するコードを持たない。
- [x] 商品名、ショップ名、説明、タグ、商品ID、購入済みかの判定、日時、保存先など、整理に必要な列だけをSELECTする。
- [x] `order_id` は購入済み判定の `IS NOT NULL` にだけ使用し、値そのものを取得・保存しない。
- [x] 氏名、住所、メールアドレス、パスワード、Cookie、セッション、決済情報を取得しない。
- [x] インストーラーで、DBパス、取得項目、非取得項目、読み取り専用、通信、非公式性を説明して明示同意を必須にし、未チェック中は「次へ」を無効化する。
- [x] 無人インストールでは `/DATAACCESSCONSENT=accept` の明示指定を必須にする。
- [x] インストーラー同意がない持ち運び実行等では、アプリ初回起動時に同じ説明と明示同意を求める。
- [x] 同意前に `BoothLibraryReader.Read` を呼ばず、拒否時はDBへアクセスせず終了する。`LoadLibraryAsync` の読み込み境界でも同意状態を再確認する。
- [x] 同意はアプリ内のポリシーページから取り消せる。取消時にBLM DBや商品ファイルを削除しない。
- [x] EXE版のアンインストール時はインストーラー側の同意記録を削除し、再インストール時に改めて確認する。分類等の設定DBは削除しない。
- [x] 同意記録は説明の版番号と更新日時だけをローカル保存する。
- [x] 独自サーバー、広告、テレメトリー、クラッシュ自動送信を持たない。
- [x] 自動画像通信はHTTPSの `booth.pximg.net`、`booth.pm` とそのサブドメインだけを許可する。
- [x] BLM DBまたは過去設定に第三者URLが含まれていても、共通ポリシーで表示前に遮断する。
- [x] 商品ページはユーザーがボタンを押した場合だけ既定ブラウザーで開く。
- [x] 商品一覧は仮想化UIとWinUIの標準画像キャッシュを使用し、公開商品情報を独自クローラーで一括取得しない。
- [x] デバッグ出力やUnity連携ログへBLM登録ID、商品フォルダー、UnityPackageのフルパス、例外全文を出さない。
- [x] 左メニュー下部へ「非公式」を常時表示し、ポリシー、README、インストーラーでも非提携・非保証を明記する。
- [x] アプリアイコンは独自制作物を使用し、BOOTH公式ロゴ素材を同梱しない。
- [x] プライバシーポリシーに取得、保存、通信、変更・削除、同意取消、問い合わせ先を記載する。

## 運用上の継続事項

- BOOTH規約・ガイドラインとBLMの配布条件が更新された場合は再確認する。
- BLMのスキーマ変更にはReader内だけで追従し、書き込み方式へ変更しない。
- 新しい通信機能、ログ、クラッシュ報告、更新確認を追加する場合は、送信先・送信内容・同意文面を再監査する。
- 公開リリースにはソース対応コミット、SHA-256、署名者、プライバシーポリシーへのリンクを記載する。

- `dotnet build VrcKaihenLibrary.slnx -c Debug -p:Platform=x64`: 警告0、エラー0。
- Release自己完結版を同意記録なしで起動し、BLM読込画面へ進まず同意ダイアログで待機することを確認した。
- アプリ同意画面にはDBパス、読み取り専用、取得・非取得情報、通信、非公式性が表示された。
- アプリ同意画面の「同意して開始」はチェック前に無効、「同意しない（終了）」は有効だった。終了後もレジストリの同意値は作成されなかった。
- Inno Setupの実画面に同じ説明と同意チェックが表示された。未チェック中は「次へ」が無効で、チェックすると即座に有効になることをUI Automationで確認した。防御的な再検査も残し、同意なしではインストール工程へ進まない。
- URL境界テストで、公式HTTPS 3件とローカルパスを許可し、HTTP、偽装サブドメイン、第三者HTTPS、Data URIを拒否した。
- `BoothLibraryReader` は `SqliteOpenMode.ReadOnly` を使用し、同Reader内に `INSERT`、`UPDATE`、`DELETE`、`REPLACE` は存在しなかった。
- アプリソースに `HttpClient`、`WebClient`、`GetAsync`、`PostAsync`、`SendAsync` による独自通信処理は存在しなかった。
- Inno Setup 6.7.3でインストーラー1.0.72.0を正常生成した。利用者向け画面では「DB」を「BOOTH Library ManagerがPC内に保存した商品情報」と表現し、未チェック中の「次へ」無効化を再確認した。SHA-256は `ECC0D094ECD018511BCB94B57A46D148CECDEEAE9381E211CBF922BC8D8CC953`。
- インストーラーのAuthenticode状態は `NotSigned`。信頼されたコード署名証明書の取得・署名・タイムスタンプは正式公開前の配布工程タスクとして残る。
