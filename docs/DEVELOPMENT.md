## コード構成

- `VrcKaihenLibrary/MainWindow.xaml(.cs)`: 一覧、検索、フィルター、詳細パネル、編集ダイアログ、Unity インポートを統括する UI
- `Models/LibraryItem.cs`: 一覧・詳細表示用モデル。商品名短縮、バッジ表示、取得種別などの表示ロジックも保持
- `Models/AvatarProfile.cs`: 登録アバター、識別名、互換性判定結果
- `Models/AssetCategories.cs`: アプリ内分類の定義
- `Services/BoothLibraryReader.cs`: BLM DB を読み取り専用で開き、BLM スキーマをアプリモデルへ変換する境界
- `Services/UserMetadataStore.cs`: 本アプリ専用 SQLite DB の作成、移行、設定保存
- `Services/AssetClassifier.cs`: BOOTH カテゴリからアプリ内分類を決定
- `Services/AvatarCompatibilityService.cs`: 識別名、手動上書き、共通素体を使った対応判定
- `Services/PurchasedPackClassifier.cs`: BLM variation から取得種別を判定
- `Services/DuplicateDownloadService.cs`: ダウンロード済みファイルの重複を扱う
- `Services/UnityImportTargetResolver.cs`: カテゴリと設定から Unity の配置先を決定
- `Services/UnityPackageImportService.cs`: `.unitypackage` を検査し、必要なら pathname を書き換えて再生成・キャッシュ
- `Services/UnityEditorBridgeService.cs`: 起動中 Unity Editor の検出とインポート要求の受け渡し
- `scripts/`: 開発証明書、MSIX ビルド・インストール、App Installer、非パッケージ版EXEインストーラー生成

## 守るべき設計上の前提

### データ安全性

- BLM DB は必ず `Mode=ReadOnly` で開く。BLM のスキーマ変更対応は原則 `BoothLibraryReader` 内に閉じ込める。
- BLM DBへ初めてアクセスする前に、読み取る項目、非取得項目、外部送信なし、公式との非提携を説明して明示同意を得る。利用者向け画面では「DB」だけで説明せず、「BOOTH Library ManagerがPC内に保存した商品情報」と表現し、技術的な保存場所を補足する。EXEインストーラーは対話ページで同意を必須にし、同意チェックが外れている間は「次へ」を無効化して、同意版をHKCUへ記録する。無人インストールは `/DATAACCESSCONSENT=accept` の明示指定を必須とする。持ち運び実行や別形式の配布ではアプリの初回ダイアログを表示し、同意前に `BoothLibraryReader.Read` を呼ばない。`LoadLibraryAsync` の読み込み境界でも同意状態を再確認し、将来のUIイベント追加による同意前アクセスを防止する。アプリ専用DBには同意内容そのものではなく同意版番号と更新日時だけを保存する。EXE版の通常アンインストールではHKCUの同意記録を削除し、再インストール時に改めて確認する。
- 手動分類、対応アバター、カテゴリ別インポート先、アプリ設定は `%LOCALAPPDATA%\VrcKaihenLibrary\library.db` に保存する。
- 未購入アバターは `avatar_profiles.is_unpurchased=1` としてアプリ専用DBだけに保存し、BOOTH商品URLとサムネイルURLも同じプロフィールに保持する。BLMの商品やDBへ追加・書き込みは行わない。同じBOOTH商品IDの購入済みアバターがBLMに現れた場合は、識別子・共通素体・対応上書きを購入済みプロフィールへ移し、未購入プロフィールを削除する。
- 旧 `%LOCALAPPDATA%\VrcKaihenManager\library.db` は、新 DB が存在しない場合だけ SQLite backup API でコピーする。旧 DB は削除しない。
- ローカルの BLM DB、ユーザー商品、生成済みキャッシュをテストの後処理で消さない。

### 分類と Unity 配置

- 自動分類は BOOTH の親カテゴリ・子カテゴリを最優先にし、商品名やタグからの推測は行わない。
- 通常は `<Unity project>/Assets/<カテゴリ別フォルダー>/` に導入する。
- 「Assets 直下」は `<Unity project>/Assets/` を意味する。
- アバター商品は常に Assets 直下へ導入し、ユーザーが変更できない。
- `.unitypackage` は .NET の `TarReader` で安全な作業領域へ展開する。通常ファイルとディレクトリ以外、リンク、絶対パス、ドライブ指定、UNC、`..`、Windows予約名、重複パスを拒否し、項目数は10万件、展開容量は圧縮サイズ比と20GBの上限で制限する。Unicodeの元ファイルパスを外部コマンドへ渡さない。またUnity 2022.3内蔵の展開処理が日本語などを含むUnityPackageファイル名の短縮パス変換に失敗する環境があるため、配置先を書き換えない場合も含め、Unityへ渡すパッケージはASCII名のキャッシュを使用する。元のダウンロードファイルは変更しない。
- 再生成物は BLM ライブラリ直下の通常フォルダー `.VrcKaihenLibraryImportCache` にキャッシュする。既存の隠し属性は次回利用時に解除し、旧キャッシュ名は可能なら移動して引き継ぐ。
- 設定画面では、一部商品が Assets 直下へのインポートを前提としている可能性と、大容量UnityPackageを分類フォルダーへ配置する場合は初回の展開・パス変更・再生成に時間がかかることを案内する。

### 対応アバター

- アバター商品を別分類へ変更した場合、その商品はアバター一覧から除外し、専用DBのプロフィール・識別名・共通素体関係・そのアバターを対象とする対応上書きも削除する。起動時同期でも過去バージョンが残したプロフィールを整理する。
- 識別名は Unicode NFKC 正規化後、大文字小文字と全角半角を吸収して照合する。
- アバターごとにメイン呼称と複数の識別名を持てる。完全な BOOTH URL は識別名として保存しない。
- 購入済みアバターを初めて同期して識別タグを自動生成するときは、商品名から正式名候補を抽出し、`オリジナル3Dモデル`、用途語、プラットフォーム名、バージョン、価格、割引・期間限定などの販促文言を除外する。日本語名・英字名の併記と、1文字の日本語名（例: `萌`）は有効な識別タグとして残し、BOOTH商品IDはURL表記との照合用に維持する。手動編集済みの識別タグには自動除外を適用しない。
- 自動識別タグの除外規則は、BOOTH公開検索の「3Dキャラクター / VRChat Avatar / ほしいものリスト順」上位100商品（2026-08-24確認）を回帰サンプルとしている。`#Menno3D` のように正式名自体へ `3D` を含む例があるため、`3D` の単純な部分一致では除外せず、`オリジナル3Dモデル` などの定型句だけを除外する。`女性型`、`男性型`、`RE`、`Blender`、複合プラットフォーム表記、`無料あり`、`セール中`、名前に連結されたバージョン接尾辞は付加語として扱う。
- 人気アバターの既定識別タグは `Data/default-avatar-identifiers.json` でBOOTH商品IDをキーに管理する。ページ番号や検索語には依存せず、2026-08-26時点の `accounts.booth.pm/wish_lists.json` の公開スキ数が7,500以上の商品を採用し、これにスキ数条件外の手動設定済み商品だけを加える。候補はBOOTHの人気順一覧に加え、複数の多数アバター対応商品の商品ID一覧を横断して補完し、シェーダー・ツール・衣装・髪型などの非アバター商品を除外する。現在はスキ数条件を満たす118商品と手動設定済みの条件外3商品、合計121商品。識別タグは原則としてメイン呼称、BOOTH商品ID、商品名・商品説明または商品IDを記載した対応商品のうちスキ上位で確認できた英字呼称とし、根拠のないローマ字推測は追加しない。商品IDが一致する自動設定プロフィールには、商品名解析よりこの対応表を優先してメイン呼称・識別タグ・商品IDを設定する。対応表を更新したアプリでは既存の自動設定も同期し直すが、`identifiers_manual=1` の手動設定は上書きしない。対応表が欠落・破損している場合は従来の商品名解析へフォールバックする。複数アバター同梱商品では商品全体の表示名をメイン呼称とし、各アバター名を追加識別タグに含める。
- 手動の追加・除外は自動判定との差分として保存する。
- 共通素体による間接一致はフィルターと件数に含め、詳細の対応アバター一覧にも `（ショコラ）` のような全角括弧付きで表示して直接対応と区別する。
- 改変アイテムの対応アバターフィルターで個別アバターを選択すると「共通素体を除外」スイッチを有効にする。オンの場合は共通素体経由の間接一致を除き、直接一致（および全アバター対応）の商品だけを表示する。通常表示と狭幅時のフィルターポップアップで状態を同期し、アバターフィルター解除時は自動的にオフへ戻す。
- 「単体購入」の自動対応判定では、購入済み variation 名だけを根拠にする。未購入 variation、説明、タグを混ぜると別アバター向け商品を誤検出する。

### BLM variation と取得種別

- `booth_item_variations.order_id IS NOT NULL` を購入済み variation の判断材料にする。
- 対応カテゴリのみ `フルパック`、`単体購入`、`無料/ギフト` を表示する。
- 明示的な full-pack 表現があれば `フルパック`。なければ購入済み variation に登録アバター識別名があれば `単体購入`。それ以外は `フルパック` 扱い。
- variation 行があるのに全 `order_id` が null の場合、BLM のローカル DB だけでは無料とギフトを区別できないため `無料/ギフト` と表示する。
- 調査時点の 281 商品中、177 商品だけが `order_id` と非空の `variation_name` を両方持つ。91 商品は購入行があっても variation 名が null、12 商品は全 order_id が null、1 商品は variation 行なし。欠損値から購入 variation を推測しない。

### UI の現行仕様

- ダウンロードファイル階層のフォルダー名と行の空き領域は階層の展開・折りたたみに使用し、左端のフォルダーアイコンだけがエクスプローラーで該当フォルダーを開く。同じ表示名のディレクトリが同じ分類内に複数ある場合だけ、見出しを `<一つ上のフォルダー名> > <ディレクトリ名>` のパンくず形式にして識別する。
- プレビュー対応画像のサムネイルへカーソルを合わせると、サムネイルの左側へ360×380px以内の拡大画像とファイル名をバルーン表示する。初回ホバー時だけ最大720px幅へ追加デコードし、カーソルが外れたらバルーンを閉じる。クリック操作やモーダルは使用しない。バルーンはポインター入力を受け取らず、サムネイルと重なっても表示・非表示を繰り返さないようにする。
- 画像編集データは、PSD・PSBをMagick.NETで縮小PNGへ変換し、KRAはアーカイブ内の `preview.png`（なければ `mergedimage.png`）を表示する。CLIP・XCF・SAI・SAI2・Affinity PhotoはWindowsのサムネイルプロバイダーを利用できる場合だけ表示し、取得できない場合は既存のファイルアイコンへ戻す。元ファイルを変更・起動せず、PSD・PSB変換はUIスレッド外で行う。
- プレビュー対象ファイルは読み込み開始時から54px四方の領域を確保し、完了までProgressRingを表示する。成功時は同じ領域を画像へ差し替え、失敗時はフォールバックアイコンへ差し替えて、ファイル名や日時の位置を移動させない。
- ファイル名規則から新旧を推測できるUnityPackageは、最も新しい版番号のパッケージを通常の親行として表示し、古い候補を18px字下げした配下へまとめる。古い行だけ薄いグレー背景と「旧バージョン」バッジを使用し、「新バージョンあり」バッジは表示しない。同名のUnityPackageが複数ある場合は、ファイル名に版番号がなくても直上の親ディレクトリ名から版番号を読み取って比較する。また、最上位ディレクトリ名が `商品名 (2)`／`商品名（2）` のような重複ダウンロード表記で、番号なしまたはより小さい番号の同名UnityPackageがある場合も、重複側をグレーの旧版行として元ファイル配下へまとめる。新旧関係として親子化できた同名ファイルでは、親と旧版の双方から「同一名あり」バッジを外す。これはファイル名・親ディレクトリ名からの推測であり、内容上の互換性や最新版であることを保証しない。
- UnityPackageのファイル名に登録済みアバターの有効な識別タグが単語境界付きで含まれる場合だけ、メイン呼称を青系のアバター名バッジとして表示する。ただし商品自体の分類が「アバター」の場合は自明なため表示しない。商品ID、URL、数字だけの識別タグ、パス中のフォルダー名、商品説明・BOOTHタグは判定に使用しない。
- ダウンロードファイル行の分類・アバター名・旧バージョン・重複バッジは、表示高のおよそ半分に当たる8px角丸で統一する。「同一名あり」の重複バッジはUnityPackageだけに表示し、テクスチャ・画像編集データ・3Dモデル・ドキュメント・その他には表示しない。
- 詳細パネルの購入種類バッジはサムネイル右端から18px離し、スクロールバー側のクリップ領域へ詰まって見えない余白を確保する。
- ダウンロードファイルのディレクトリ階層は兄弟単位のアコーディオンとし、同じ親を持つディレクトリを開いた場合は、先に開いていた同階層のディレクトリを閉じる。別の親配下や別分類の展開状態は変更しない。
- 詳細パネルのダウンロードファイル分類内では縦スクロールを持たず、展開したファイル・ディレクトリを外側の詳細パネルスクロールへ伸ばす。分類内と詳細パネルのスクロールが多重にならない構成を維持する。
- ダウンロードファイルの「画像編集データ」分類には、PSD・CLIPなどの制作データだと分かりやすいペイント／カラーパレット系アイコンを使用する。
- Unityインポート先ページの分類別入力一覧はカード状の枠線で囲まず、「設定を保存」ボタンを入力欄の直下にまとめて一体のフォームとして表示する。
- 「使い方」のメニューアイコンはカラー絵文字ではなく、他のメニューと馴染む単色アウトラインの初心者マークとする。最下部のバージョンチップは11pxの太字と上下5pxの内側余白で表示する。
- アプリの表示名は「VRC改変ライブラリ（BOOTH Library Manager拡張）」。内部プロジェクト名、名前空間、保存先、MSIX identity は互換性維持のため `VrcKaihenLibrary` のまま変更しない。
- 左メニューは76px幅で「アバター」「改変アイテム」「ショップ」「BOOTHタグ」「Unityインポート先」（2行）、「表示設定」「使い方」の順に並べ、最下部に独立した「ポリシー」と実行中アセンブリのバージョンチップを置く。「使い方」のアイコンには初心者マークを使用する。「Unityインポート先」ページは分類別フォルダー名とAssets直下設定を担当し、「表示設定」ページは商品名表示、右詳細パネルサイズ、アバター・改変アイテムカードサイズを担当する。ページ先頭の大見出しと同義の小見出しは重複表示しない。カードサイズは「小」150px基準、「中（既定）」180px基準、「大」230px基準で、`application_settings.card_size_preset` に保存する。「使い方」は最初にアバターのメイン呼称・識別タグと誤分類を確認し、その後に商品検索、詳細確認、Unityインポートへ進む流れをアイコン付きで説明する。ポリシーページでは読み取る情報、通信、Unity操作権限、保存・変更・削除、非公式性を明記する。アバター画面はアバター分類だけを独立表示し、購入状態フィルター、改変アイテムと同等のソート、再読み込み、未購入アバター追加を提供する。「未購入アバター追加」は一覧フィルター行でソートの右隣に配置する。未購入カードには右上へ「未購入」バッジ、購入済みカードには該当時「更新あり」バッジを表示する。
- 未購入アバターの登録・編集では、名前、BOOTH商品URL、サムネイルURL、メイン識別名、複数の追加識別子、共通素体を設定する。識別タグと共通素体選択は購入済みアバターの編集と同じUIを使い、アバター候補は検索・複数選択できるサムネイル付きカードで表示する。未購入アバターも候補に含め、その登録サムネイルを表示する。カード選択ではBOOTHを直接開かず右詳細パネルを表示し、見出しと編集ボタンは通常商品と同じ「アイテム詳細」「アイテム情報編集」とする。ショップ、商品ページ、DL商品、ダウンロード一覧、BLM再取得、対応設定リセット、重複削除は出さない。編集は同じ登録フォームを使い、右上メニューから登録削除できる。
- 未購入アバターのBOOTH商品URLは `booth.pm/ja/items/<ID>`、`booth.pm/items/<ID>` に加え、BOOTH公式のショップサブドメイン形式 `<shop>.booth.pm/items/<ID>` も受け付ける。HTTPS、既定ポート、BOOTH配下のホスト、商品パスを個別に検証し、保存時は商品IDから標準URLへ正規化する。
- 改変アイテム画面はタイトルを「改変アイテム」とし、用途の説明文を添える。従来の商品一覧からアバター分類を除外し、カテゴリタブにもアバターを表示しない。
- ショップ画面はショップサムネイルと名称のカード一覧で、名称検索と再読み込みだけを置く。カードを選ぶと改変アイテム画面へ移動し、そのショップのフィルターを適用する。
- BOOTHタグ画面は全改変アイテム（アバター分類を除く）の販売商品タグを商品単位で重複排除して集計し、タグ名と該当商品件数を件数降順で表示する。説明文でもクリック時の絞り込みを案内する。タグ名検索と全データ再取得を提供し、タグカードを選ぶと改変アイテム画面へ移動して該当タグで絞り込む。
- アバター、ショップ、BOOTHタグの検索・フィルターは見出しの下段へ左揃えで置き、説明文は横幅不足時に折り返す。未購入アバター追加は全データ再取得の左隣へ置く。
- 各ページ右上のライブラリ全体を同期する操作は「全データ再取得」と表示する。
- アプリ名見出しは先頭にアプリアイコンを表示し、`Segoe UI Variable Display` のセミボールドと濃いチャコール色を使う。タイトルバー左上にも同じ意匠のマルチサイズ ICO を設定する。
- 改変アイテム、アバター、ショップ、BOOTHタグのカードは列数に応じて横幅いっぱいへ広がる可変幅で並べる。商品カードは正方形サムネイルを基準にし、商品名は2行、ショップ名は1行。
- 取得種別、対応アバター件数、更新ありバッジはサムネイル右上に縦積み。専用メタデータ行へ移す変更は取り消し済み。
- 詳細は右側のスライドパネル。タグ、商品ページ、ダウンロードファイル、取得 variation、対応アバターを表示する。「DL商品」は置かず、同じ幅の「データ再取得」を商品ページの右側に配置する。取得種別バッジは一覧と同様にサムネイル右上へ表示し、対応根拠は枠線で丸く囲んだ疑問符からツールチップで確認できる。
- 詳細のダウンロードファイルは、ファイル名または相対フォルダー名に含まれるテキストで即時絞り込みできる。絞り込み中は一致件数と全件数を表示する。Unityパッケージ分類はファイル単位で表示し、テクスチャからその他までの分類はディレクトリ階層を既定表示する。階層には、その分類のファイルが直下に存在するディレクトリだけを含め、該当ファイルのない中間ディレクトリは省略して最も近い表示対象階層へ接続する。ディレクトリを展開すると直下の該当ファイルと子階層を表示する。PNG、JPEG、BMP、GIF、TIFF、WebPにはローカル画像のサムネイルを表示する。非パッケージ版で任意ドライブの `file://` URIをXAMLへ直接渡さず、`StorageFile` からストリームを開いて108px幅へ縮小デコードすることで、空白、環境依存文字、絵文字を含むパスにも対応する。
- BOOTH商品に登録されたタグは、右詳細パネルのダウンロードファイル下に `BOOTHタグ（3）` のような件数付きアコーディオンで配置し、商品詳細を開いた初期状態では閉じておく。展開後は白背景・薄い枠線・8px角丸のチップで表示し、クリックすると改変アイテム画面へ移動してそのタグで絞り込む。
- リモートサムネイルの自動取得はHTTPSの `booth.pximg.net`、`booth.pm` とそのサブドメインだけを共通ポリシーで許可し、BLM DBや過去の手動登録データに任意URLが入っていても第三者URLへ自動接続しない。ローカル画像は従来どおり表示する。商品一覧は仮想化されたGridViewで表示し、WinUIの標準画像キャッシュを利用するため、一覧外の画像を独自クローラーで一括取得しない。
- デバッグ出力とUnity連携ログには、BLM登録ID、商品フォルダーやUnityPackageのフルパス、例外全文を出さない。Unityの操作確認に必要なパッケージ名だけを表示する。アプリは独自サーバー、テレメトリー、クラッシュ自動送信を持たない。
- 検索、カテゴリ、対応アバター、ショップ、BOOTHタグ、「無料/ギフトのみ」、「更新ありのみ」のフィルターは合成され、変更時は1ページ目へ戻る。後者2つはチェックボックスで指定する。900px未満では検索と全フィルターをポップアップへまとめる。
- 改変アイテムのカテゴリタブとソート欄の直下には、選択中カテゴリの色を使った横幅いっぱいのアクセント線を表示する。
- カテゴリアクセント線はタブと隙間なく接続する。ウィンドウ幅1400px未満ではフィルターを2行にし、「無料/ギフトのみ」以降を次の行へ送る。見出しは再取得ボタンの表示領域を優先して可変幅にする。
- 右詳細パネルの左端は16px幅のリサイズ領域をドラッグして300〜720pxの範囲にリサイズでき、領域上では左右矢印カーソルを表示する。リサイズ領域は12px幅のレイアウト列から内容側へ重ね、操作範囲を維持しながら詳細内容との間にも適度な余白を残す。表示設定ページでは「小」340px、「中（既定）」420px、「大」560pxと「手動設定」を表示し、ドラッグ完了後と保存済み幅がプリセット以外の場合は「手動設定」を選択状態にする。プリセット選択とドラッグによる選択幅を `application_settings.detail_panel_width` に保存して次回起動へ引き継ぐ。ウィンドウを狭めた場合は一覧領域を最低360px残す上限へ一時的に縮小し、保存幅自体は維持する。幅380px未満では編集ボタンをアイコン表示にする。
- Unityインポート先の保存、および表示設定（商品名短縮、詳細パネルのプリセット幅、カードサイズ）の変更完了は、画面右下の自動消去ポップアップだけで通知し、各項目の下には完了文言を表示しない。詳細パネルをドラッグして手動幅へ変更した場合はポップアップを表示しない。
- 縦スクロールバーは操作しやすい横幅を維持しつつ、表示後のWinUI標準テンプレート内にある上下端ボタンを0pxへ縮め、上下の余白を最小化する。標準リソースの `ScrollBarSize` はテンプレート内で静的解決されアプリ側の同名リソースでは上書きできないため使用しない。一覧を含むルートと右詳細パネルの読み込み時に共通処理を適用する。改変アイテム、アバター、ショップ、BOOTHタグの各一覧はスクロール領域を従来より右へ12px広げ、縦スクロールバーを画面端寄りへ配置する。
- 標準ページサイズは50件で、50・100・200件を選べる。
- 商品名の「スマート短縮」は設定で無効化できる。短縮規則を広げる場合、アバター名や商品固有名を消さないサンプル確認が必要。
- スマート短縮は `【 Sale_中 】` のように空白・記号が混ざるセール表記に加え、`UP TO 50% OFF`、周年記念セール、対応人数の「18人」、`33colors` のような色数、装飾付きの `MA対応`・`Update`、`VRChat用ヘアモデル`、登録アバター名に続く「用」なども補助文言として除去する。人数・割合・色数・`全118種`・`23types` などの数値部分は特定値へ固定せず、任意の半角・全角数字を受け付ける。商品固有名の型番やバージョン番号は単独では除去しない。
- 同じ商品フォルダー内のUnityPackageについて、ファイル名と親フォルダー名から製品系列・版番号を比較し、同系列のより大きい版番号がローカルに存在する旧版へ「新バージョンあり」を表示する。BLM通知の有無は判定に使わず、系列を特定できない場合は誤表示を避ける。
- 同期、再読み込み、重複確認、Unityインポートなどの進捗・完了・エラーは画面右下のアニメーション付きポップアップへ表示する。エラーは赤いアクセントと大きい警告アイコンを使い、自動では閉じない。
- 初回起動ではコンテンツ領域に読み込み中オーバーレイを表示する。BLM DB が未作成、更新途中、ロック中、または初期テーブル作成途中の場合は2秒間隔で最大10回再試行し、その間はエラー扱いにしない。再試行後も読み取れない場合だけ最終エラーを表示する。BLM DB は再試行中も読み取り専用で扱う。
- 新規インストール後の初回データ読み込み成功時だけ「使い方」ページを開き、`application_settings.first_launch_completed` を記録する。2回目以降は通常どおり「アバター」から開始する。既存DBまたは旧名DBから更新したユーザーは初回扱いにせず、アップデート直後に使い方へ強制移動させない。
- 非パッケージ版では進捗ポップアップの表示・退場に XAML `Storyboard.Begin()` を使うと `Microsoft.UI.Xaml.dll` で起動直後にクラッシュするため、Windows Composition の `Visual` アニメーションを使う。非パッケージReleaseの実起動確認なしにStoryboardへ戻さない。
- 進捗ポップアップは右下に配置し、Composition の絶対 `Offset`（レイアウト位置を上書きする）ではなく `Translation` で右方向へ出入りさせる。表示時は右から小さくバウンドし、退場時は一度左へ溜めてから右へ戻る。

## 名前変更後に残している互換処理

- 旧アプリ DB から新 DB への初回コピー
- Unity の旧 UPM bridge `com.vrckaihenmanager.import-bridge` の除去
- `.VrcKaihenManagerImportCache` から `.VrcKaihenLibraryImportCache` への移動

これらは既存ユーザーの移行用です。単なる旧名の検索結果として削除しないでください。MSIX identity は `usa-mishin.VrcKaihenLibrary` で、旧 identity とは Windows 上で別アプリとして扱われます。

## MSIX と配布

- 開発用の自己署名証明書は、テスト PC の Local Machine `TrustedPeople` に信頼登録が必要で、管理者 PowerShell を使う。
- `scripts/Build-Msix.ps1` が署名済みパッケージを `artifacts/msix` に生成する。
- `Build-Msix.ps1 -Version` はビルド中だけ package manifest の版番号を置換し、MSIXのパッケージ版番号とアセンブリ表示版番号の両方へ同じ値を渡して、アプリ内のバージョン表示が `1.0.0.0` に戻らないようにする。終了時はmanifestを元へ戻す。MSIXの更新判定に使われるため、配布のたびに版番号を増やす。
- `scripts/New-AppInstaller.ps1` は公開 HTTPS URL が決まった後の自動更新用。
- 正式配布では自己署名証明書を使わず、信頼されたコード署名サービスまたは証明書を使う。

## EXE インストーラーと配布

- `scripts/Build-ExeInstaller.ps1` は x64 の自己完結型・非パッケージ版を publish し、Inno Setup 6 で `artifacts/installer` に単一のセットアップEXEを生成する。
- 画面構成、主要機能、データ形式などの大きめの改修を完了した際は、コードのビルド確認だけで終えず、版番号を上げたEXEインストーラーも生成して上書きインストールと実起動を確認する。
- インストール先はユーザー単位の `%LOCALAPPDATA%\Programs\VrcKaihenLibrary` で、管理者権限を要求しない。同じInno Setup `AppId` と、より大きい版番号で上書き更新する。
- ユーザーデータ `%LOCALAPPDATA%\VrcKaihenLibrary` はインストール先の外に置き、更新・通常アンインストールで削除しない。
- MSIX版とEXE版は別インストールになる。移行時はMSIX版をアンインストールしてからEXE版を導入するが、共通のユーザーデータは引き継ぐ。
- GitHub Releasesにはタグと対応するセットアップEXEを添付する。`artifacts/` や署名秘密鍵はGitへコミットしない。手順の正本は `docs/EXE-DISTRIBUTION.md`。
- オープンソース公開前は `docs/OPEN-SOURCE-CHECKLIST.md` に従い、個人情報、秘密情報、ローカルのAI支援ツール設定、ユーザーデータ、Git作者情報を現行ファイルと履歴の両方で監査する。
- 未署名EXEでも証明書の事前登録なしで実行できるが、SmartScreen警告が出る場合がある。正式証明書取得後はセットアップEXEにも署名する。

## 検証方針

BOOTH Library Managerとの連携に関するプライバシー・通信・ログ・誤認防止の監査結果は `docs/BOOTH-INTEGRATION-AUDIT.md` を参照する。公開前は同文書の完了項目を再確認し、運営元から回答を得た場合は条件と確認日を追記する。

変更範囲に応じ、最低限次を確認します。

1. `dotnet build VrcKaihenLibrary.slnx -c Debug -p:Platform=x64`
2. BLM DB を読む変更では、DB が読み取り専用であることと欠損値を許容すること
3. UI 変更では、一覧、詳細パネル、編集ダイアログ、スクロール、ウィンドウ終了を実機確認
4. Unity 導入変更では、通常配置、Assets 直下、アバター、キャッシュ再利用、悪意ある archive path の拒否を確認
5. 配布変更では対象形式（MSIXまたはEXE）をReleaseビルドし、新規インストール、上書き更新、起動、アンインストール、ユーザーデータ保持を確認

自動テストプロジェクトはまだありません。純粋ロジック（分類、タイトル短縮、取得種別、互換判定）を変更する際は、回帰を防ぐためテストプロジェクト追加を優先候補にしてください。

## 一覧・詳細 UI の現行仕様

- 改変アイテムの「無料/ギフト」「更新あり」は ToggleSwitch で表示し、「フィルタをクリア」とともに BOOTH タグフィルタの直後へ必要最小幅で横並びにする。ウィンドウ幅が 1400px 未満では、検索欄と3つのセレクト操作の幅を守るため、この3項目だけを次の行へ左詰めで折り返す。900px 未満では検索・フィルタのフライアウトへまとめ、同じ状態を同期する。
- 「全データ再取得」は各一覧の検索操作と同じ行の右端に配置する。改変アイテムでは分類タブ・ソート行のソート右側に配置する。
- 改変アイテムの分類は、ツールバーの実利用幅と実際の分類タブ幅を比較し、「ギミック」までが収まらなくなる時だけ分類セレクターへ切り替える。実利用幅には開いている詳細パネルの幅も反映し、パネルの開閉・ドラッグリサイズに追従する。「アニメーション」以降が隠れる間は横スクロール可能なタブを維持する。セレクターは選択中タブと同じ背景色・角丸・下線を保ち、右端に展開矢印を加えた外観とする。十分な幅へ戻せば横並びタブへ復帰する。
- アバター一覧のソートは改変アイテムと同じアイコン・選択名・フライアウト形式を使用する。
- 詳細パネルで BLM の未読更新通知がある商品は、ダウンロードファイル欄の直前に赤い通知バーを表示する。
- `(1)` などの重複ダウンロードフォルダーに同名 UnityPackage がある場合は、バージョン違いと同様に片方をグレー表示して親パッケージへまとめるが、両方の「同一名あり」表示は残し、「旧バージョン」は表示しない。通常のバージョン違いでは「旧バージョン」を表示し、「同一名あり」は表示しない。
- 共通素体由来の対応アバターは、直接一致したアバターを親として `ショコラ（シフォン・プラム）` の形式でまとめて表示する。
- 左メニュー下部のバージョンチップから、公開可能な概要だけを記載したアプリ内バージョン情報ページを開く。アプリ起動時と同ページを開いた時にGitHub Releasesの最新版を確認し、最新版より古い場合はチップ右上へ赤い更新バッジを表示する。自動確認は通知のみで、リリースページのブラウザー表示はユーザーがバージョン情報を開いた場合に限る。
- 左メニューと、アバター・改変アイテム・ショップ・BOOTHタグのクリック可能なカードは、マウスオーバー時に手のポインターを表示する。
- 左メニューでページを切り替えた際は、選択項目に短いスケール反応を付け、ページ内容を下から8pxのフェード・スライドで表示する。長時間の演出にせず、操作を妨げない200ms前後の遷移とする。
